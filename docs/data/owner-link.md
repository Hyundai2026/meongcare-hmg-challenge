# 보호자 프로필 서버 저장과 차 연결 형식 (v1)

보호자 웹이 반려견 프로필을 서버(Firestore)에 저장하고, 차 앱이 연결 코드 한 번으로 그 프로필을 읽는 데 쓰는 문서들이다.
코드가 아니라 이 문서가 기준이다. 형식을 바꾸면 이 문서와 예시 JSON부터 고친다.

- 예시: [owner-link.example.json](owner-link.example.json). 문서 경로마다 논리 형식을 보인다 (타임스탬프는 ISO 8601 UTC 문자열로 적는다).
- 프로필 필드 자체는 [pet-profile.md](pet-profile.md) v1이다. 이 문서는 서버의 **어디에, 누가, 무엇을** 두는지만 정한다.
- 보안 규칙: `firebase/firestore.rules`. 점검: `npm --prefix firebase run check-rules` (R14~R24)
- 계획: [docs/plans/completed/014-owner-link.md](../plans/completed/014-owner-link.md)

## 흐름 (TV 로그인 방식)

```
[차, 정차 중]  [보호자 웹과 연결] → linkCodes/{코드} 만들기 → 화면에 "K7P 3QX"를 크게
[보호자 웹]    [차와 연결] → 코드 입력 → 한 번에 쓰기: 코드 claim + petProfiles/{나}/readers/{차}
[차]          코드 문서에 보호자가 생긴 것을 본다 → 코드 문서 지우기 → petProfiles/{보호자} 읽기
```

- 차에서는 글자를 입력하지 않는다 (AGENTS.md 규칙 3). 코드는 차가 만들고 보호자가 폰에 입력한다.
- 연결 화면은 정차 중에만 보인다 (Pleos 주행 규제: QR 로그인·설정 금지, [ux-guidelines.md](../pleos/ux-guidelines.md)).
- 보호자와 차 모두 Firebase **익명 계정**이다 (사용자 결정 U1). 보호자 웹은 서버 저장에 동의할 때 익명 계정을 만든다.

## 문서

| 경로 | 필드 | 쓰는 쪽 | 읽는 쪽 |
|---|---|---|---|
| `owners/{ownerUid}` | `schemaVersion: 1`, `consentVersion: 1`, `consentedAt`(서버 시각) | 보호자 (동의할 때 만듦) | 보호자 |
| `petProfiles/{ownerUid}` | pet-profile v1 필드 그대로. 단 **`photoDataUrl`은 늘 `null`** | 보호자 | 보호자, 연결된 차 |
| `petProfiles/{ownerUid}/private/photo` | `photoDataUrl` (pet-profile의 사진 규칙. 400,000자 이하) | 보호자 | **보호자만** |
| `petProfiles/{ownerUid}/readers/{carUid}` | `linkCode`(연결에 쓴 코드), `createdAt`(서버 시각) | 보호자 (claim과 같은 한 번에 쓰기) | 보호자, 그 차 |
| `linkCodes/{code}` | `schemaVersion: 1`, `carUid`, `createdAt`(서버 시각), `ownerUid`(`null` → 보호자 uid), `claimedAt`(`null` → 서버 시각) | 차 (만들기·지우기), 보호자 (claim) | 아래 "연결 코드" |

- 프로필 문서의 `updatedAt`은 pet-profile처럼 **ISO 8601 UTC 문자열**이다 (서버 타임스탬프가 아니다). 브라우저에 저장한 프로필과 같은 형식으로 옮기기 위해서다.
- 사진은 차가 읽을 수 없는 문서로 따로 둔다 (사용자 결정 U3). 차는 진료에 필요한 정보만 받는다. 병원에 보내는 카드에도 사진이 없다 ([emergency-case.md](emergency-case.md)).
- 프로필 문서는 동의 문서(`owners/{ownerUid}`)가 있어야 만들 수 있다.

## 연결 코드

| 항목 | 규칙 |
|---|---|
| 글자 | 대문자와 숫자 31종: `23456789` + `ABCDEFGHJKMNPQRSTUVWXYZ` (`0`·`1`·`I`·`L`·`O`는 헷갈려서 뺀다) |
| 길이 | 6자 (약 8.9억 가지) |
| 화면 | 세 글자씩 띄어 `K7P 3QX` |
| 웹 입력 | 소문자·공백·하이픈을 받아 대문자 6자로 바꾼다. 빠진 글자가 있으면 보내지 않는다 |
| 만료 | `createdAt` + **10분** (서버 시각으로 판단한다. 차 화면의 남은 시간은 차 시계로 어림한다) |
| 한 번만 | `ownerUid`가 `null`일 때만 claim할 수 있다. 연결되면 차가 코드 문서를 지운다 |
| 읽기 | 차 본인, claim한 보호자, 또는 (claim 전이고 만료 전이면) 로그인한 누구나 **한 건만**. 목록 조회는 막는다 |
| 겹침 | 차가 만들 때 같은 코드가 있으면 새 코드로 다시 만든다 (세 번까지) |

- 웹은 코드를 못 찾음·만료·이미 씀을 **한 문구로** 보인다: "코드를 찾지 못했거나 만료됐어요. 차에서 새 코드를 받아 주세요." 어느 경우인지 알려 주지 않는다.
- 차가 화면을 떠나면 claim 안 된 코드를 지운다.

## 연결과 해제

- 차 하나에 보호자 한 명이다. 연결된 차가 새로 연결하면 이전 `readers` 문서를 먼저 지운다.
- 보호자 한 명은 여러 차와 연결할 수 있다.
- 해제: 차 [연결 끊기] 또는 보호자 웹 "연결된 차"에서 `readers/{carUid}`를 지운다. 그 뒤 차의 프로필 읽기는 거부된다 (403).
- 차는 보호자 쪽에 아무것도 쓰지 않는다. 남는 것은 익명 `carUid`와 연결 시각뿐이다.

## 차가 읽을 때

차는 `petProfiles/{ownerUid}` 한 건만 읽는다. pet-profile의 "읽는 쪽 규칙"을 그대로 따른다.

| 응답 | 차의 결과 |
|---|---|
| 200, 형식 맞음 | 프로필 (진료 카드·병원 전송에 쓴다) |
| 200, 형식 틀림·버전이 1이 아님 | 읽지 못함 (짐작하지 않는다) |
| 403 | 연결 끊김 (보호자나 차가 해제했다) |
| 404 | 등록 안 됨 (보호자가 프로필을 지웠다) |
| 그 밖 (네트워크, 5xx) | 읽지 못함 |

- **연결된 뒤 읽지 못하면 샘플로 대신하지 않는다.** "반려견 정보를 받지 못했어요"를 보인다. 틀린 의료정보를 보이는 것보다 안전하다.

## 알려진 한계

- 연결 코드를 마구 대입해 보는 것은 막지 못한다. 속도 제한에는 서버 함수(Functions)나 App Check가 필요한데, 지금은 Spark 요금제에 함수가 없다 (012). 6자·10분·한 번만으로 시연 범위에서는 충분하다고 본다.
- 만료된 코드 문서는 차가 지우지 못하고 남을 수 있다 (자동 정리 없음). 만료 뒤에는 아무도 claim하거나 읽지 못한다.
- 보호자 익명 계정은 그 브라우저에만 있다. 브라우저 사이트 데이터를 지우면 서버의 프로필을 고칠 수 없다 (차 연결은 남는다). 화면과 동의 문구에 알린다.

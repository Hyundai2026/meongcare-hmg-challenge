## 무엇을 했나

확정 디자인 프로토타입(`docs/product/design/prototype/MeongCare car.html`)의 1번 화면 "차량 연결"을 보호자 웹 연결 화면에 적용했다. 카드 없이 왼쪽 정렬로 안내문 → 큰 연결 코드 → 진행 막대 → "남은 시간 mm:ss"(1초마다) → [새 코드] + 글자 버튼 [닫기]. 연결되면 "✓ 연결 완료" → 큰 메시지 → 반려동물 줄 → [확인]. 다음 화면들이 쓸 디자인 토큰(색·글자·간격·모서리·버튼 높이)도 놓았다.

## 어떻게: 핵심 결정과 이유

- **디자인 토큰을 별도 객체로** (`ui/theme/DesignTokens.kt`, `LocalDesignTokens`): 화면을 하나씩 옮기는 동안 Material colorScheme을 바꾸지 않아 다른 화면이 그대로다. 값은 프로토타입 JS의 TH 표(라이트·다크)에서 그대로 옮겼다.
- **mm:ss + 진행 막대** (사용자: 디자인은 프로토타입대로): `LinkUiState.Waiting`과 기존 테스트를 바꾸지 않으려고, ViewModel에 `waitingSince`(코드 만든 시각)를 더하고 화면이 1초마다 `linkCountdownOf`로 계산한다.
- **폰트 파일을 넣지 않음** (사용자: 다운로드로 시간 끌지 말 것): Pleos에는 Asta Sans가 시스템 UI 폰트로 있고, 이 PC 에뮬레이터는 기본 한글 글꼴이라 조금 두껍게 보인다.
- **"체험 모드 시작"은 뺌** (앱에 없는 기능). 문구는 앱 문구 그대로, "연결 완료"·"남은 시간"만 새로.
- **화면 폭 비율로 줄이기**: 프로토타입은 앱 영역 1682 기준이다. 태블릿(약 1280dp)에서는 0.76배로 글자·간격·버튼을 같이 줄인다. 차량 화면은 1.0.

## 사용한 Pleos SDK / API / 권한

- 없음.

## 확인

- 테스트: tester가 37개를 더했다 (남은 시간 계산, `waitingSince` 계약, 토큰 값이 프로토타입 TH 표와 같은지). 전체 1366개 통과. 버그 1개(기기 언어 숫자)를 `Locale.ROOT`로 고쳤다.
- 화면: 태블릿 에뮬레이터 시연 모드에서 대기 화면 확인. 다크 모드·세로 화면·만료·실패·연결됨 화면은 사용자 결정으로 확인하지 않았다.

## 주의점 / 남은 일

- 다른 화면은 아직 옛 디자인이다. 화면을 다 옮기면 Material colorScheme을 토큰 값으로 맞추고 `Color.kt`의 임시 색과 `LinkText`를 정리한다.
- 프로토타입 문구("차량 연결", "새 코드 발급", "시작")와 앱 문구가 다르다. 맞출지는 기획에서 정한다.

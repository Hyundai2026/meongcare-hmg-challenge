# 개발 노트

작업이 끝날 때마다 무엇을 왜 했는지 남긴다. 기획서의 "개발 계획"(5번 항목: 구현 방식·범위·사용한 SDK/API), PT 자료, 시연 순서를 쓸 때 원천이 된다.

## 위치

```
docs/notes/<git user.name>/YYYY-MM-DD-<작업-이름>.md
```

- 폴더 이름은 그 작업을 한 사람의 `git config user.name` 값이다. 공백은 `-`로 바꾼다.
  - Claude가 쓸 때도 커밋 작성자(사용자)의 폴더에 쓴다.
- 작업 이름은 브랜치 이름에서 접두사를 뺀 것과 맞춘다.
  - 예: 브랜치 `feat/vehicle-speed-flow` → 노트 `2026-11-05-vehicle-speed-flow.md`

## 언제 쓰나

- 작업 하나(계획 하나 또는 기능 브랜치 하나)가 끝났을 때, `/ship`으로 dev에 반영하기 전에 쓴다. 커밋마다 쓰는 게 아니다.
- 노트는 별도 커밋으로 낸다: `docs(notes): <작업 이름>`

## 다른 문서와의 차이

| 문서 | 언제 | 내용 |
|---|---|---|
| `docs/plans/` | 작업 전·중 | 할 일과 진행 상태 |
| `docs/notes/` | 작업 후 | 한 일, 결정 이유, 시연 방법 (사람이 읽는 기록) |
| `docs/pleos/` | 알게 됐을 때 | 검증된 SDK 사실 (출처 포함) |

- SDK에 대해 새로 확인한 사실은 노트에만 두지 않는다. `docs/pleos/`에도 반영한다 (AGENTS.md 규칙 7).

## 무엇을 했나

차를 세운 상태에서 **[진료 카드 만들기] → 큰 버튼으로 증상 고르기 → 진료 카드**가 만들어진다. 카드에는 고른 증상과 보호자가 등록한 기존 병력·알레르기·복용 약물이 들어간다 (컨셉 그림의 오른쪽 화면). 카드에서 [병원에 전화](전화 앱 열기)와 [길 안내 시작]을 하고, 도착해서 차를 세우면 같은 카드가 "도착했어요"로 다시 떠서 수의사에게 보여 줄 수 있다.

- 반려견 정보는 아직 보호자 웹과 연결되지 않아 **시연용 샘플 "보리"**다. 화면에 그렇게 알린다.
- 차에서 글자를 입력하는 곳이 없다 (정차 화면의 메모 칸도 뺐다).

## 어떻게: 핵심 결정과 이유

자세한 표: [docs/architecture.md](../../architecture.md) "주행 상태 × 길안내 상태 화면 조합" 2단계 표

- **주행 안전 규칙은 그대로 두고, 정차 화면 안에서 한 번 더 고른다.** 기존 `homeContentOf`(주행·모름이면 무조건 주행 화면)는 손대지 않았다. 정차일 때만 새 `parkedContentOf`가 처음 화면 / 증상 고르기 / 카드를 고른다. 그래서 주행 화면, 길안내, 시연 시나리오 코드는 한 줄도 바뀌지 않았다.
- **흐름 (사용자 결정)**: 길안내는 카드의 [길 안내 시작]에서만 시작한다. 안내 전 카드에 [닫기]를 더했다 (그림에 없음). 카드 줄에 **알레르기**를 더했다 (그림에 없음, 수의사에게 꼭 필요).
- **증상 12개 (사용자 결정)**: 호흡 곤란, 경련, 쓰러짐, 출혈·상처, 이물 삼킴, 구토, 설사, 기침, 기운 없음, 식욕 없음, 절뚝거림, 배 부풂. 급한 것을 앞에 두었고(의학 검토는 아님), 카드에도 누른 순서가 아니라 이 순서로 적는다.
- **카드 "자동 생성"은 AI 없이 규칙으로** 조합한다 (`medicalCardOf`). Claude API는 문의 A1 답 이후 팀 논의.
- **고른 증상은 메모리(`AppContainer`의 `MedicalCardSession`)**에 둔다. Fake 길안내와 수명이 같아서 안내 시작 → 주행 → 도착까지 남는다. 앱 프로세스가 죽으면 사라진다 (알려진 한계).
- **반려견 프로필은 모든 데이터 모드에서 Fake**다. 프로필 출처를 인터페이스(`PetProfileSource`)로 빼서, 서버가 생기면 바꿔 끼운다. Kotlin 모델과 나이 계산은 보호자 웹과 같은 형식·규칙이다 ([docs/data/pet-profile.md](../../data/pet-profile.md)).
- **병원 전화 (사용자 결정)**: `ACTION_DIAL`로 전화 앱에 번호를 띄우기만 한다 (권한 없음, 걸지 않음). 전화 앱이 없으면 번호를 크게 보여 준다. 시연용 번호 `02-0000-0000`.
- **색**: 시스템 라이트·다크를 따른다 (Pleos 가이드: 주간·야간 자동 조정). 다크는 그림처럼 남색 배경, 카드는 테마와 상관없이 흰 바탕.
- **화면 배치**: 폭 840dp 이상이면 그림처럼 아바타 왼쪽·정보 오른쪽, 좁으면 위아래. 증상 버튼은 폭에 맞춰 2~4열. 아래 버튼 줄은 스크롤 밖에 고정해서 긴 목록이어도 밀리지 않는다.
- 사진은 저작권 때문에 아직 쓰지 않고 이름 첫 글자("보")를 그린다. 사진 자리는 남겨 두었다.

## 사용한 Pleos SDK / API / 권한

- 새 Pleos SDK 없음, 새 `pleos.car.permission.*` 없음.
- Android 표준 `Intent.ACTION_DIAL` (권한 없음, `<queries>` 없음).

## 확인

- **단위 테스트 306개 통과** (기존 185 + 직접 쓴 41 + tester 경계 테스트 80). tester가 버그 1건을 짚었고 고쳤다: 반려견 정보가 늦게 오는 출처(나중 서버)에서는 버튼을 눌러도 화면 상태가 바뀌지 않았다.
- 검증 파이프라인 통과, release 빌드 성공. 주행·길안내·시연 시나리오 코드와 기존 테스트 파일은 바뀌지 않았다 (`git diff`로 확인).
- **Pleos 에뮬레이터** (debug Fake·시연 모드):
  - 처음 화면 → 증상 4열 → 카드(넓은 배치) → [병원에 전화] → 차의 "전화" 앱이 열림 (번호는 보이지 않음) → 돌아오면 같은 카드
  - 고르는 중에 기어 D → 주행 화면 → P → 고르던 선택 그대로
  - [길 안내 시작] → D → 도착 → P → "도착했어요" 카드(같은 증상) → [닫기] → 처음 화면. 에러 로그 없음
- **일반 폰 에뮬레이터**: 다크 모드 좁은 배치(남색 배경, 흰 카드), [병원에 전화] → 구글 전화 앱에 번호가 채워져 열림
- **확인하지 못한 것**: Pleos에서 내비 옆 반쪽 창, release APK를 기기에 설치해 보기, 전화 앱이 없는 기기의 번호 패널(테스트로만), 시스템 뒤로 키, 실차 전화(문의 B4)

## 시연 방법 (영상 촬영용)

**Pleos 에뮬레이터 + release APK** (README "Pleos 에뮬레이터에서 시연하기"와 같다)

1. Cold boot → 앱 실행 → Virtual Console로 기어 P (`adb forward tcp:8088 tcp:8088`, [2026-11-05-real-driving-state.md](2026-11-05-real-driving-state.md)의 `vc()`)
2. [진료 카드 만들기] → 호흡 곤란, 기침 → [카드 만들기 (2개)] → 카드 (여기서 [병원에 전화]를 보여 줘도 된다)
3. [길 안내 시작] → 기어 D → 주행 화면 "병원까지 N분" (약 24초)
4. "도착했어요" → 기어 P → 도착 카드 → [닫기]

**일반 폰 에뮬레이터 + release APK**: 2번까지 하고 [길 안내 시작]만 누르면 출발 → 도착 → 주차까지 저절로 간다 (약 30초).

- 야간 화면(그림과 같은 남색)을 찍으려면 `adb shell cmd uimode night yes` (폰). 찍은 뒤 `no`로 되돌린다.

## 기획서 5번 "개발 계획"에 넣을 문장 (기획 담당에게)

> 차에서는 글자를 입력하지 않는다. 정차 중 큰 버튼으로 증상을 고르면, 보호자가 미리 등록한 의료정보(기존 병력·알레르기·복용 약물)와 합쳐 진료 카드를 규칙에 따라 만든다. 카드에서 병원 전화(전화 앱 열기)와 길안내를 시작하고, 주행 중에는 카드를 숨겨 남은 시간만 보이며, 도착해 정차하면 같은 카드를 수의사에게 보여 준다. 현재 반려견 정보와 병원은 시연용 샘플이며, 보호자 웹과의 연결과 AI 정리는 대회 규정 확인 뒤 진행한다.

## 주의점 / 남은 일

- 서버로 보호자 웹 프로필 받기 (A1), 카드 AI 정리 (A1·팀 논의), 실차 전화 (B4), 프로세스 재시작 시 증상 복원, 사진 표시
- **Pleos 전화 앱이 번호를 보여 주지 않았다.** 실차에서도 그렇다면 카드에 병원 번호를 늘 보이게 하는 편이 낫다 (지금은 시연 안내 줄에만 번호가 있다).
- 폰 세로 + debug 패널에서는 카드가 짧게 보인다 (release에는 패널이 없다). 칩이 "골든리트/리버"처럼 낱말 중간에서 줄바꿈된다.
- Pleos 화면에서 글자가 시스템 UI보다 작아 보이는 문제는 그대로다 (계획의 있으면 좋음 C).
- 하지 않은 있으면 좋음: 예시 JSON 파일 대조 테스트(A), debug 패널에서 Fake 프로필 바꾸기(B), 넓은 화면 글자 키우기(C)

## 무엇을 했나

PawCare의 "병원까지 길안내 → 남은 시간 표시 → 도착하면 진료 카드" 흐름을 가짜(Fake) 데이터만으로 처음부터 끝까지 돌게 했다. 실제로 운전하지 않고도 시연 영상을 찍을 수 있다.

- **정차 화면**: 목적지 "시연용 동물병원"과 [병원으로 안내] 버튼이 있다. 안내 중에는 "병원까지 N분"과 [안내 취소]를 보여준다.
- **주행 화면**: 큰 글씨 "병원까지 N분"과 병원 이름만 보여준다. 도착하면 "도착했어요"를 띄운다. 버튼은 없다.
- **도착 화면** (정차한 뒤): "도착했어요", 병원 이름, 진료 카드 자리표시, [닫기].
- 진짜 내비 연결(Pleos NaviHelper)은 아직 하지 않았다. Real 모드에서는 빈 구현(항상 "안내 없음")이 끼워진다.

## 어떻게: 핵심 결정과 이유

자세한 표: [docs/architecture.md](../../architecture.md) "주행 상태 × 길안내 상태 화면 조합"

- **길안내 인터페이스(`GuidanceSource`)는 NaviHelper 모양에 맞추되, 아직 모르는 것에 묶이지 않게 했다.**
  - 남은 시간은 `Duration`으로 둔다. NaviHelper `TripInfo.eta`의 단위(초/분)와 뜻(남은 시간/도착 시각)을 아직 모르기 때문이다. 변환은 나중에 Real 래퍼 안에서만 하면 된다.
  - 목적지는 이름과 좌표만 필수로 둔다. `poiId`가 필수인지 모른다.
  - 도착은 일회성 이벤트지만 "상태"로 둔다. 사용자가 [닫기]를 누를 때까지 도착 화면을 유지해야 하기 때문이다.
- **Fake 두 개(주행 상태, 길안내)는 따로 두고, FAKE 전용 `FakeTripScenario`가 둘을 잇는다.**
  - 안내를 시작하면 3초 뒤 주행, 도착하면 5초 뒤 정차로 바꾼다. 그래서 영상을 찍을 때 debug 패널을 누르지 않아도 된다.
  - 실제 차에서도 주행 상태(차량)와 길안내(내비 앱)는 서로 모르는 출처다. 각 Fake가 Real과 같은 책임만 지게 해야 화면 코드가 Real에서도 그대로 돈다.
  - 버린 대안: Fake 길안내가 주행 상태를 직접 바꾸기. 클래스는 하나 줄지만 Real과 책임이 달라진다.
- **화면 조합은 순수 함수(`homeContentOf`)로 뺐다.** 주행 중이면 도착해도 진료 카드를 보여주지 않는다는 안전 규칙을 JVM 테스트로 검증할 수 있다. 기존 `HomeViewModel`과 그 테스트는 건드리지 않았다.
- **사용자 결정 (2026-11-05)**
  - 주행 중 화면에 [안내 취소] 버튼을 두지 않는다. 취소는 정차 중에만 한다. 주행 중 터치를 줄이기 위해서이고, 실제 차에서는 내비 앱에서도 취소할 수 있다.
  - 주행 중 [병원으로 안내] 버튼도 아직 두지 않는다. 문의 B1(주행 중 사용 선언)과 B2(STT) 답을 보고 정한다.
  - 샘플 병원은 가상 이름 "시연용 동물병원". 실제 병원 이름은 제3자 권리 문제로 피했다. 좌표는 Pleos NaviHelper 문서 예시 좌표다.
  - 도착 화면은 [닫기]를 누를 때까지 유지한다.
- **`FakeGuidanceSource`는 상태를 잠금 안에서 바꾼다.** 취소 버튼(Main 스레드)과 시간 흐름(백그라운드 스레드)이 동시에 상태를 바꿀 때, 취소 뒤에 이전 진행이 상태를 덮어쓰지 않게 하려는 것이다.

## 사용한 Pleos SDK / API / 권한

- **없음.** 새 SDK, 새 의존성, 새 `pleos.car.permission.*` 모두 0개.
- NaviHelper(`requestRoute`, `onTripInfo`, `onDestinationArrived`, `cancelRoute`)는 후속 작업이다. 확인할 질문은 계획 파일의 "후속 계획(Real 길안내)으로 넘기는 질문"에 모아 두었다.

## 확인

- **단위 테스트 89개 통과** (기존 26 + 새 63)
  - 직접 쓴 것 25개: Fake 길안내 8, 시나리오 4, Real 자리표시 2, GuidanceViewModel 8, 화면 조합 3
  - tester가 쓴 경계 테스트 38개. 계약 위반 버그는 없었다.
- **검증 파이프라인** (`assembleDebug testDebugUnitTest lintDebug`) 통과
- **화면** (`/verify`, 일반 폰 에뮬레이터 `my_avd` 1080x2400, debug, Fake)
  - 시연 흐름 전체, 취소 경로 2개, 가로·다크, Real 전환, 크래시 0건을 확인했다.
  - 주행 화면의 입력칸 0개, 누를 수 있는 요소 0개 (debug 패널 제외)
  - 찾아서 고친 것: 도착 화면 제목 "시연용 동물병원에 도착했어요"가 "요" 한 글자만 다음 줄로 넘어갔다 → "도착했어요"와 병원 이름을 두 줄로 나눴다.
  - Pleos 에뮬레이터에서는 확인하지 않았다. Real 길안내가 없어서 Fake 모드는 일반 에뮬레이터와 결과가 같다.

## 시연 방법

1. debug 빌드를 설치하고 실행한다. 화면 아래 debug 패널이 "DEBUG · Fake"인지 본다 (아니면 [Fake로 전환]).
2. 정차 화면에서 [병원으로 안내]를 누른다. 그 뒤로는 손대지 않아도 된다.

| 누른 뒤 | 화면 |
|---|---|
| 0초 | 정차: "경로를 찾는 중" + [안내 취소] |
| 1초 | 정차: "병원까지 12분" |
| 3초 | **주행**으로 바뀜: 큰 글씨 "병원까지 11분" (2초마다 1분씩 줄어듦) |
| 25초 | 주행: "도착했어요" / "정차하면 진료 카드를 볼 수 있어요" |
| 30초 | **정차**로 바뀜: 도착 화면 (진료 카드 자리표시 + [닫기]) |

3. [닫기]를 누르면 처음 화면으로 돌아간다.

- 속도를 바꾸려면 `FakeGuidanceTiming`(남은 시간, 줄어드는 간격)과 `FakeTripTiming`(출발·주차 지연)의 기본값을 고친다. 기본값을 확인하는 테스트(`FakeGuidanceSourceBoundaryTest`)도 같이 고친다.
- 화면 녹화: `adb shell screenrecord /sdcard/demo.mp4` → 끝나면 Ctrl+C → `adb pull /sdcard/demo.mp4`

## 주의점 / 남은 일

- **휴대폰 가로 화면에서는 debug 패널이 높이의 약 1/3을 차지한다.** 그래서 [안내 취소]·[닫기]가 화면 아래로 밀린다(스크롤하면 닿는다). release에는 패널이 없다. 가로로 영상을 찍으려면 debug 패널 접기를 먼저 만든다 (계획의 있으면 좋음 A).
- **release 빌드(항상 Real)에서는 길안내가 동작하지 않는다.** Real 주행 상태가 항상 "모름"이라 주행 화면만 보인다. 제출 APK를 어떻게 할지는 따로 정해야 한다.
- 남은 일:
  - Real 길안내 (NaviHelper). Pleos 에뮬레이터에서 내비 앱이 요청을 받는지부터 확인한다.
  - 병원 검색 (카카오 로컬 + Firebase). 문의 A1 답을 기다린다.
  - 진료 카드 내용 (Claude API)
  - 정차 화면의 메모 입력칸 자리표시 정리
  - Real ETA를 모를 때는 `Duration.INFINITE`가 아니라 `null`로 넘긴다 (tester 관찰: INFINITE면 "1분"으로 보인다).

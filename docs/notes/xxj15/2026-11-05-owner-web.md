## 무엇을 했나

보호자가 **폰 브라우저에서 반려견의 프로필(사진, 이름, 품종, 생년월일 또는 나이, 성별)과 의료정보(주요 질환, 알레르기, 복용 약)를 미리 등록하는 웹**을 만들었다. 차에서는 글자를 입력하지 않고, 집에서 등록해 둔 정보로 진료 카드를 만들게 하려는 것이다 (팀 컨셉 그림의 왼쪽 "반려견 정보 등록(웹)").

- 지금은 **그 브라우저(localStorage)에만 저장**한다. 차 앱과는 아직 연결되지 않았고, 화면에도 그렇게 알린다.
- 웹과 차 앱이 같이 따를 **프로필 형식 문서**를 만들었다: [docs/data/pet-profile.md](../../data/pet-profile.md)

## 어떻게: 핵심 결정과 이유

자세한 표: [docs/architecture.md](../../architecture.md) "보호자 웹"

- **같은 저장소 `web/`, React + Vite + TypeScript** (사용자 결정). 웹팀이 React를 알고, 심사위원이 저장소 하나에서 앱과 웹을 본다. 의존성은 6개뿐이고 버전을 정확히 고정했다. ESLint는 넣지 않았다 (사용자 결정, TypeScript strict가 대신).
- **저장은 브라우저 먼저, 서버는 나중** (사용자 결정). 서버(Firebase)는 주최측 문의 A1(외부 서버 사용 가능 여부) 답을 기다린다.
  - 저장소를 인터페이스(`PetProfileRepository`)로 뺐다. localStorage 구현이 앱의 Fake 자리, 나중 Firebase 구현이 Real 자리다. 바꿔 끼워도 화면 코드는 그대로다.
- **형식 문서가 기준이다.** 웹 코드가 아니라 `docs/data/pet-profile.md`가 기준이고, 웹 테스트가 예시 JSON(보리)을 읽어서 문서와 코드가 어긋나면 테스트가 깨진다.
  - `schemaVersion: 1`을 둔다. 모르는 버전은 읽지 않는다. 차 앱이 짐작해서 약 정보를 틀리게 보여 주면 안 되기 때문이다.
  - 빈 배열은 "없음"이 아니라 "등록하지 않음"이다.
  - 나이 계산 규칙(12세 3개월, 말일 맞추기)을 문서에 적어 차 앱도 같은 규칙을 쓰게 했다.
- **사진은 브라우저에서 긴 변 512px JPEG로 줄여** 저장한다. 캔버스로 다시 그려서 원본의 촬영 위치(EXIF)가 빠진다.
- **화면은 컨셉 그림을 따랐다.** 탭은 의료정보·기본정보 2개이고 의료정보가 먼저 열린다. 진료이력 탭과 알림 아이콘은 기능이 없어서 두지 않았다 (사용자 결정).
- **하네스: dev에 들어갈 때만 웹을 검사한다** (사용자 결정 4b). 검증 파이프라인·pre-push·CI(`web.yml`)가 `npm --prefix web run check`를 돈다. 커밋 직전·턴 종료는 지금처럼 Android만 본다.
  - 파이프라인은 웹 의존성을 자동 설치하지 않는다. 설치가 안 됐으면 멈추고 `npm --prefix web ci`를 하라고 알린다. 패키지 설치는 사람이 확인하고 한다는 결정과 맞추려는 것이다.
- **화면 확인은 Python Playwright 스크립트**(`web/scripts/verify_screens.py`)로 한다. `/verify`는 Android용이다. 날짜를 2026-11-05로 고정하고 폰 크기 두 폭(390·360)으로 13개 시나리오를 돈다. 콘솔 에러나 다른 주소로 가는 요청이 있으면 실패다 (의료정보가 밖으로 나가지 않는다는 확인).

## 확인

- **단위 테스트 216개 통과** (`npm --prefix web ci` 후 `check`)
  - 직접 쓴 것 86개: 형식 읽기·쓰기, 나이 계산(1년 치 모든 날 × 0~30세 왕복), 저장소, 화면 상태, 프로필·의료정보 폼 검증, 문구, 사진 크기
  - tester가 쓴 경계 테스트 130개. 버그 2건을 짚었고 고쳤다:
    - 저장 시각(`updatedAt`)을 너무 너그럽게 읽었다 (`"1"`도 날짜로 읽음). 이제 ISO 8601 UTC만 읽는다. 차 앱(Kotlin `Instant`)과 결과를 맞추려는 것이다.
    - 나이를 바꾸지 않고 다시 저장하면 30년보다 오래된 추정 생년월일이 남았다.

## 시연 방법 (영상·기획서 스크린샷용)

1. 저장소 루트에서 `npm --prefix web ci` (처음 한 번) → `npm --prefix web run dev`
2. PC 브라우저로 `http://localhost:5173` → F12 → 기기 모드(Ctrl+Shift+M) → iPhone 12 Pro 같은 폰 크기
   - 폰으로 직접 보려면 같은 Wi-Fi에서 `npm --prefix web run dev -- --host` → 터미널의 `Network:` 주소
3. 순서: 빈 화면 → [반려견 등록하기] → 사진(**팀원이 직접 찍은 강아지 사진**, 저작권 때문) · 이름 "보리" · 품종 · 생년월일 · 수컷 → [저장] → 의료정보 탭 [+ 의료정보 추가하기] → 심장질환 / 특정 단백질 알레르기 / 심장약·1일 1회 → [저장] → 새로고침해도 그대로
4. 처음부터 다시 하려면 개발자 도구 → Application → Local Storage → `owner-web.pet-profile` 삭제
5. 스크린샷만 필요하면 화면 확인 스크립트가 찍은 `.claude/.cache/web/*.png`를 써도 된다 (사진은 합성 그러데이션이다)

## 기획서 5번 "개발 계획"에 넣을 문장 (기획 담당에게)

> 보호자는 폰 웹에서 반려견 프로필과 의료정보(주요 질환·알레르기·복용 약)를 미리 등록한다. 차에서는 글자를 입력하지 않고 이 정보로 진료 카드를 만든다. 첫 버전(구현 완료)은 정보를 브라우저에 저장하며, 웹과 차 앱이 같은 데이터 형식을 쓰도록 설계했다. 서버(Firebase) 연동과 차 앱 연결은 대회 규정(외부 서버 사용 가능 여부) 확인 뒤 진행한다.

- "차 앱이 웹 정보로 진료 카드를 만든다"는 **아직 구현 전**이다. 기획서에는 계획으로 쓴다 (출품 유의사항: 사실과 다르면 선정 취소).

## 주의점 / 남은 일

- **차 앱 쪽 (다음 작업)**: `PetProfile` 도메인 모델(Kotlin)과 Fake(예시 JSON의 "보리" 값)를 만들고 도착 화면의 진료 카드 자리표시를 채운다. 형식 문서의 "Kotlin 대응" 표와 나이 규칙을 따른다.
- **서버 (A1 답 이후)**: Firebase Auth + Firestore 구현, 차 앱 연결(정차 중 QR 페어링 안). 할 일 목록: architecture.md "Firebase로 옮길 때 할 일"
- **앱 이름이 정해지면** `web/src/config.ts`의 `APP_NAME`과 Android `strings.xml` 두 곳을 바꾼다. 지금 웹은 "PawCare"다.
- 하지 않은 "있으면 좋음": 녹화 옵션, 브라우저 뒤로가기로 편집 닫기, "이 브라우저 정보 지우기" 버튼, 실제 폰 확인, Safari 엔진 확인
- 저장 공간 부족 문구가 "사진을 빼고 다시 저장해 보세요"라서, 사진이 없을 때도 같은 문구가 나온다. 사소해서 두었다.

## 무엇을 했나

제출용 release APK로도 심사위원이 PawCare 핵심 흐름을 볼 수 있게 **시연 모드**를 만들었다. 흐름은 병원 길안내 시작 → 주행 중 남은 시간 → 도착 → 정차 후 진료 카드 자리다. 진짜 길안내(Pleos NaviHelper)는 아직 없어서 길안내는 시연용이고, 화면에 그렇게 알린다.

- **Pleos 에뮬레이터**에서는 Virtual Console로 기어를 바꾸면 앱이 따라 바뀐다. P에서 [병원으로 안내]를 누르고 D로 바꾸면 남은 시간이 줄고, 도착 뒤 P로 바꾸면 도착 화면이 뜬다. 왼쪽 차량 정보와 앱이 맞는다.
- **일반 폰 에뮬레이터**에서는 [병원으로 안내]만 누르면 출발부터 주차까지 저절로 이어진다 (약 30초).
- 정차 화면 길안내 카드와 도착 화면에 "시연용 길안내예요. 실제 내비게이션과는 아직 연결되지 않았어요."를 보여 준다.

## 어떻게: 핵심 결정과 이유

자세한 표: [docs/architecture.md](../../architecture.md) "데이터 모드 (Fake / 시연 / Real)"

- **데이터 모드를 셋으로 늘렸다: Fake / 시연 / Real.** release는 시연 모드로 고정했다 (사용자 결정). 모드를 바꾸는 UI는 release에 없다.
  - Real 길안내(NaviHelper)가 생기면 release 기본을 다시 정한다. `feat(di): release 빌드를 시연 모드로 고정`(`a9334b5`) 커밋만 되돌리면 이전(항상 Real)으로 돌아간다.
- **시연 모드의 주행 상태는 기기에 따라 자동으로 고른다** (사용자 결정). 심사위원이 APK를 어디서 돌릴지 모르기 때문이다 (문의 A2).
  - 차량 기기(`FEATURE_AUTOMOTIVE`, Pleos 에뮬레이터·실차)에서는 진짜 주행 규제 값을 따른다.
  - 일반 폰에서는 진짜 주행 상태가 항상 "모름"이라 안내를 시작할 수조차 없다. 그래서 가짜 출발·주차 시나리오로 흐름을 잇는다.
- **주행 중에만 남은 시간이 줄어든다** (사용자 결정).
  - P에 서 있는 동안에는 "병원까지 12분"이 그대로이고, 멈추면 최대 한 단계까지 더 줄고 멈춘다. 실제 내비게이션도 차가 서 있으면 남은 시간이 줄지 않는다.
  - Fake 길안내에 "진행 조건"을 생성자 인자로 넘기는 방식이다. 도메인 인터페이스(`GuidanceSource`)는 Real(NaviHelper)과 다르게 바꾸지 않았다.
  - 진행 조건은 안내 한 번에 한 번만 구독하고, 도착·취소하면 끊는다. Real 주행 상태는 구독할 때마다 차량에 새로 연결하기 때문이다.
  - **도착도 주행 중에만 온다.** 마지막 1분을 세는 도중에 차를 세우면 다시 출발할 때까지 도착을 미룬다. tester가 계약 충돌로 짚어서 이쪽으로 정했다.
- **어떤 구현을 끼울지는 순수 함수 표(`sourcePlanOf`)가 정한다.** Android를 몰라서 모드 × 기기 조합 전체를 JVM 테스트로 확인한다.
- **시연용 표시는 정차·도착 화면에만 넣었다** (사용자 결정). 주행 화면은 정보를 늘리지 않으려고 그대로 뒀다. 주행 화면 작은 줄에 이미 "시연용 동물병원"이 보인다. 출품 유의사항(제출 서류가 사실과 다르면 선정 취소) 때문에 숨기지 않는다.
- **시연 모드 안내 중에는 차량 연결이 둘이다** (화면용, 남은 시간용). Pleos 에뮬레이터에서 둘이 같은 값을 받는 것을 확인했다. 하나로 묶는 것(`shareIn`)은 화면 안전 규칙과 얽혀서 미뤘다.

- **release APK**:
  - 서명 없는 APK는 설치가 거절된다 (`INSTALL_PARSE_FAILED_NO_CERTIFICATES`).
  - 기존 debug 키로 서명한 **확인용 사본**(`.claude/.cache/`, 커밋 안 함)을 두 에뮬레이터에 새로 설치했다. debug 패널 없이 처음부터 시연 모드였다. 일반 폰은 흐름이 저절로, Pleos는 기어 조작대로 끝까지 돌았다. 크래시 없음.

## 시연 방법 (영상 촬영용)

**Pleos 에뮬레이터 + release APK** (차량특화성이 가장 잘 보인다)

1. 에뮬레이터를 **Cold boot**로 켜고 APK를 설치·실행한다. 기어는 P다.
2. Virtual Console을 연다: `adb forward tcp:8088 tcp:8088` → 브라우저 `http://127.0.0.1:8088/` → Emulation Controls → Motion → Gear Selection.
   - 명령으로 바꿀 수도 있다: [2026-11-05-real-driving-state.md](2026-11-05-real-driving-state.md) "시연 방법"의 `vc()` 함수
3. [병원으로 안내] → "병원까지 12분" (P에서는 그대로)
4. 기어 D → 주행 화면, 남은 시간이 2초마다 1분씩 준다 (약 24초)
5. "도착했어요" → 기어 P → 도착 화면(진료 카드 자리) → [닫기]

**일반 폰 에뮬레이터 + release APK**: [병원으로 안내]만 누르면 끝까지 저절로 돈다 (약 30초).

**화면 녹화**: `adb shell screenrecord /sdcard/demo.mp4` → 끝나면 Ctrl+C → `adb pull /sdcard/demo.mp4`

## 기획서 5번 "개발 계획"에 넣을 문장 (기획 담당에게)

> 제출 APK는 **시연 모드**로 동작한다. 주행/정차 판단은 차량의 주행 규제 값(AAOS `CarUxRestrictions`)을 실제로 따른다. Pleos 에뮬레이터에서 기어를 바꾸면 화면이 주행용·정차용으로 바뀐다. 병원 길안내는 Pleos NaviHelper 연동 전이라 **시연용 시뮬레이션**이다. 정해진 시간대로 남은 시간이 줄며 주행 중에만 줄어든다. 병원은 가상의 "시연용 동물병원"이다. 앱 화면에도 시연용임을 표시한다. 2차 PT 전까지 NaviHelper 실연동을 목표로 한다.

마지막 문장은 팀이 정할 일정이다. 확정 전에는 빼거나 고친다.

## 주의점 / 남은 일

- **제출 전에 필요한 것** (이번 범위 밖):
  - 팀 정식 서명 키와 팀명·앱 이름. 그다음 `/release-apk`로 만든다 (사용자 실행). 확인용 사본은 debug 키로 서명했으므로 제출하면 안 된다 (Pleos 보안 가이드: 배포용 앱에 디버그 인증서 금지).
- Real 길안내(NaviHelper). 생기면 release 기본 모드를 다시 정한다.
- 시연 속도: 2초에 1분이라 약 24초면 도착한다. 영상에 너무 빠르면 시연 모드 전용 시간 값을 늘린다 (계획의 있으면 좋음 A).
- 정차 화면의 "메모 (정차 중에만 입력)" 칸은 심사위원에게 의미가 없다. 지울지는 기획 결정이다 (계획의 있으면 좋음 B).
- 시연 문구가 휴대폰 세로 화면에서 "아/직"처럼 낱말 중간에서 줄이 바뀐다 (한국어 글자 단위 줄바꿈). 사소해서 두었다.
- Pleos 화면에서 글자·버튼이 작아 보이는 문제는 그대로다.
- 차량 연결 두 개를 `shareIn`으로 묶는 일은 구독자가 더 늘면 한다.
- 지금 두 에뮬레이터에는 확인용 release 사본이 깔려 있다.

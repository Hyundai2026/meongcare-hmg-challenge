## 무엇을 했나

정차 중 증상 고르기 화면에서 **[말로 증상 고르기]**를 누르고 한 문장으로 말하면, 차 안의 음성 엔진(Pleos SpeechToText `ON_DEVICE`)이 받아쓰고 키워드 규칙이 맞는 증상 버튼을 눌러 준다. 사용자는 버튼으로 확인·수정한 뒤 지금처럼 카드를 만든다. 버튼만으로도 같은 카드를 만들 수 있다.

## 어떻게: 핵심 결정과 이유

- **음성은 추가 입력 수단이다. 버튼 흐름은 그대로 둔다.** 콘솔의 STT는 아직 "준비 중"이고, 운영사무국 답(B2)은 `ON_DEVICE`를 써도 되는지 직접 말하지 않았다. 안 된다는 답이 오면 음성만 뺀다.
- **정차 중에만 쓴다** (사용자 결정 2026-11-05). 주행 중에는 아무 입력도 받지 않는다는 규칙(AGENTS.md 규칙 3)을 지킨다. 주행 중 음성은 문의 B1의 답을 보고 정한다.
- **한 문장, 최종 결과만, 더하기만.** 엔진은 말이 잠깐 끊기면 거기서 인식을 끝낸다 (관찰). 찾은 증상은 지금 선택에 더하기만 하고, 빼는 것은 버튼으로 한다. 사용자가 모르는 사이 선택이 빠지지 않게 하려는 것이다.
- **증상 찾기는 AI 없이 키워드 규칙으로 한다** (`domain/voice/SymptomMatcher.kt`). 네트워크가 필요 없고, 결과가 늘 같고, 테스트할 수 있다.
  - 공백·문장부호를 지운다. "토마토", "커피"처럼 키워드를 품은 낱말은 먼저 가린다.
  - 부정을 알아듣는다. "구토는 안 했어요"는 구토가 아니다. "고·는데·지만·서"에서 문장을 끊는다 ("토해서 기운이 없어요"는 구토 + 기운 없음).
  - 검증은 세 가지로 한다: 규칙마다 이름 붙은 테스트, 받아쓴 문장 모음(`app/src/test/resources/voice/symptom-sentences.tsv`, 에뮬레이터에서 실제로 받아쓴 문장 포함), tester의 경계 테스트.
  - Pleos 엔진이 "가쁘게"를 "바쁘게"로 받아쓴 것을 보고 키워드를 더했다.
- **듣기 한 번마다 `SpeechToText`를 새로 만들고 놓는다.** `initialize`가 4~35ms라 느리지 않고, 화면 전환이나 실패 뒤 복구할 상태가 없다.
- **`stop()` 바로 뒤에 `release()`하지 않는다** (이번에 찾은 버그). SDK의 `stop()`은 코루틴으로 미뤄지고 `release()`는 그 자리에서 연결을 끊는다. 그래서 바로 이어 부르면 음성 서비스가 녹음을 멈추지 않았다. 앱을 꺼도 계속됐다. 이제는 `stop()` 뒤 인식 끝이 오거나 1초가 지나면 놓는다. 자세히: [sdk-notes.md](../../pleos/sdk-notes.md) "앱 구현(010)에서 본 것".
- 시간 제한:
  - 시작 뒤 3초 안에 응답이 없으면 "쓸 수 없음"
  - 인식이 끝난 뒤 2초 안에 최종 결과가 없으면 "말소리 없음"
  - 시작 뒤 15초가 지나면 "말소리 없음"
  - 시간은 이벤트마다 다시 재지 않는다 (tester가 찾은 문제를 고침).
  - 무음이면 엔진이 아무 이벤트도 보내지 않아서 15초 제한이 끝낸다.
- 모드별 구성은 `di/VoicePlan.kt`가 정한다.

  | 상황 | 음성 입력 |
  |---|---|
  | Fake 모드 | 예시 문장 + 시연용 표시 |
  | 시연·Real 모드, 차량 기기 | 실제 마이크 |
  | 시연 모드, 일반 폰 | 예시 문장 + 시연용 표시 |
  | Real 모드, 일반 폰 | 없음 |

  - `SourcePlan`에 칸을 더하지 않은 이유: 칸을 더하면 기존 테스트를 고쳐야 하고, 따로 두면 음성만 빼기 쉽다.
- `RECORD_AUDIO`는 선언하지 않았다 (사용자 결정). 에뮬레이터에서는 음성 서비스가 대신 녹음했다. 실차에서도 그런지는 모른다.
- 빼는 법 ([architecture.md](../../architecture.md) "음성 입력 빼는 법"):
  - 화면에서만 빼기: `VOICE_INPUT_ENABLED = false` 한 줄
  - APK에서 빼기: 위 한 줄 + 커밋 두 개(`2d6d0c3` 래퍼, `f1610b4` 래퍼 수정) revert
  - 되돌린 상태에서 빌드와 433개 테스트가 통과하는 것을 확인했다.

## 사용한 Pleos SDK / API / 권한

- `ai.pleos.playground:SpeechToText:3.3.1` (전이 의존성 `ai.pleos.playground.security:universal-access:0.6.0`)
- `SpeechToText(context, Mode.ON_DEVICE)`, `initialize(OnInitializeListener)`, `addListener(ResultListener)`, `setLocale(Locale.KOREA)`, `request()`, `stop()`, `removeListener()`, `release()`
- `ResultListener`:
  - 쓰는 것: `onReady`, `onStartedRecognition`, `onUpdated`, `onEndedRecognition`, `onError`
  - 무시하는 것: `onUpdatedEpdData`, `onUpdatedRms`
- `ErrorType` 처리:
  - `TIMEOUT` → 말소리 없음
  - `MIC_ERROR`·`AUDIO_ERROR` → 마이크
  - 그 밖 → 쓸 수 없음 (새로 생긴 값도 이쪽으로)
- 권한:
  - `pleos.car.permission.STT_SERVICE`: 2026-11-03 팀 승인. 보호 수준 `normal`이라 설치하면 허용된다.
  - `android.permission.INTERNET`: AAR이 더한다.
  - `RECORD_AUDIO`: 없음.
- 앱 등록(Client ID/Secret)은 쓰지 않는다. `ON_DEVICE`는 필요 없다.

## 시연 방법

**Pleos 에뮬레이터 (실제 음성):**

1. Mac 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 에뮬레이터를 켜는 앱(터미널 또는 VS Code)을 허용한다.
2. 마이크를 넘기는 옵션으로 Cold boot한다:

   ```
   emulator -avd pleos_connect -no-snapshot-load -no-snapshot-save -gpu host -allow-host-audio
   ```

   마이크가 꺼져 있으면 `adb emu avd hostmicon`. 다 찍으면 `hostmicoff`.
   자세히: [emulator-setup.md](../../pleos/emulator-setup.md) "에뮬레이터 마이크 (Mac)"
3. 기어 P → **[진료 카드 만들기]** → **[말로 증상 고르기]** → "듣고 있어요"가 보이면 한 번에 말한다: "강아지가 갑자기 토하고 숨을 가쁘게 쉬어요".
4. 화면에 다음이 보이고, 두 버튼이 눌린다:
   - "알아들은 말: …"
   - "골랐어요: 호흡 곤란, 구토"
5. 필요하면 버튼으로 고치고 → **[카드 만들기]** → 그다음은 009 흐름(길안내 → D → 도착 → P).

- 에뮬레이터 마이크 소리가 늦거나 겹쳐 들릴 때가 있다 (에뮬레이터 현상). 문장 사이에 몇 초 쉰다.
- 영상은 debug 패널을 Fake로 바꿔 찍어도 된다. 화면에 "시연용 음성 입력"이라고 나온다.
- 스피커로 `say`를 틀어 넣으면 방이 시끄럽다. 사람 목소리로 하거나 Fake로 찍는다.

**일반 폰 + release APK:** [말로 증상 고르기]를 누르면 예시 문장 3개를 차례로 받아쓴다. 실제로 듣지 않고, 화면에 시연용이라고 표시한다.

## 기획서 5번 "개발 계획"에 넣을 문장 (기획 담당에게)

> 정차 중 증상 고르기 화면에서 마이크 버튼을 누르고 한 문장으로 말하면, Pleos SpeechToText SDK(`ON_DEVICE`: 차량 안의 음성 엔진이라 네트워크와 앱 등록이 필요 없다)가 받아쓴 문장을 키워드 규칙으로 증상 버튼에 옮긴다. 사용자는 버튼으로 확인·수정한다. 버튼만으로도 같은 카드를 만들 수 있다. 주행 중 음성 입력은 대회 문의 답에 따라 확장한다.

- 사실과 다르게 쓰지 않도록 주의한다:
  - 지금은 **정차 중에만** 쓸 수 있다.
  - 증상 찾기는 **AI가 아니라 키워드 규칙**이다.
  - 일반 폰에서는 시연용 예시 문장이다.

## 주의점 / 남은 일

- 문의 B1(주행 중 음성)과 B2(STT를 써도 되는지)의 답을 기다린다. 안 된다고 하면 위 "빼는 법"대로 뺀다.
- 실차에서 `RECORD_AUDIO` 없이 녹음되는지 모른다.
- 오디오 포커스(듣는 동안 음악이 줄어드는지)는 문서에 없고, 확인하지 않았다.
- 무음이면 15초를 기다린다. 줄이려면 "준비 뒤 N초 동안 받아쓰기가 없으면 끝" 규칙을 더해야 한다. 그러려면 tester 테스트 하나("준비된 뒤에는 최대 듣기 시간까지 기다린다")를 같이 바꿔야 한다.
- 듣는 중에 앱 프로세스가 죽으면 음성 서비스는 다음 `request()`가 올 때까지 계속 녹음한다. 서비스 쪽 동작이라 앱에서 막을 수 없다.
- 알려진 오탐 가능성: "이 물건"이 이물 삼킴으로 잡히고, "땀에 절어"가 절뚝거림으로 잡힌다. 고칠 문장이 생기면 TSV에 줄을 더하고 키워드 표를 고친다.
- 있으면 좋음 A~D는 하지 않았다. A(녹음한 예시 음성을 엔진에 넣기)는 사용자가 고른 대비책이라 PT(12/03) 전에 할 만하다.
- 위 "확인하지 못한 것"(D2·D3·D7·P7·P8, release D1)이 남아 있다.

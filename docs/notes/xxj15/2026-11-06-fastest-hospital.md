## 무엇을 했나

- **응급일 때 "현실적으로 가장 빨리 진료받을 수 있는 병원"을 알려 준다.** 진료 카드에서 [가장 빨리 진료받을 곳 찾기]를 누르면 제휴 병원을 "이동 시간 + 병원이 알린 대기 시간"이 짧은 순으로 보여 준다.
- 병원을 고르고 [출발]하면 그 병원으로 차 내비 길안내가 시작되고, **진료 카드와 도착 예정 시간이 병원 화면에 바로 뜬다.** 주행 중에는 남은 시간이 갱신되고, 도착·취소도 알린다.
- **병원 웹(시연용, `/hospital/`)**: 병원 직원이 대기 시간·혼잡도·응급 접수를 큰 버튼으로 알리고, 들어온 카드를 실시간으로 본다.

## 어떻게: 핵심 결정과 이유

- **사용자 결정 (2026-11-06)**: 문의 A1 답 "외부 API·자체 서버 써도 된다". 병원 웹은 `web/` 안의 둘째 페이지, 카드는 [출발] 때 자동 전송, 병원 목록은 제휴 병원만(카카오는 나중), 병원 웹 접근은 병원별 코드가 든 링크(U1), [카드 없이 길안내만] 둔다(U2), 사진·차 위치는 보내지 않는다(U3), `firebase` 웹 의존성과 `firebase/` 폴더 추가(U4).
- **서버는 Firebase Firestore + 익명 Auth, Spark(무료).** Functions를 쓰지 않아 Blaze(카드 등록)가 필요 없다. 개발·시연은 PC의 Firebase 에뮬레이터다. 진짜 프로젝트("MeongCare", 서울)는 만들어 두었고 연결은 아직이다.
- **이동 시간은 직선 거리 어림** (하버사인 × 1.25 ÷ 21km/h, 화면에 "약"). 후보마다 길안내 없이 실제 경로 시간을 받는 Pleos API가 확인되지 않았다 (`requestRoute`는 안내를 시작한다). 계수는 에뮬레이터 내비 관찰 1건(12km·35분)에 맞춘 시연용 가정이다.
- **순위 규칙**: 이동 + 대기 합 → 이동 → 이름 → id. 대기 정보가 30분보다 오래됐거나 없으면 순위 뒤, 쓸 만한 정보로 응급 접수를 안 한다고 했으면 따로(고를 수 없음). 위치를 모르면 다른 위치로 대신 계산하지 않고 대기 시간 순.
- **시연 병원 5곳**은 "가장 가까운 곳이 가장 빠른 곳은 아니다"가 한 화면에 보이게 짰다 (가까운 병원 2.5km지만 대기 60분 → 3위).
- **차 앱은 Firestore REST로 붙는다** (Firebase Android SDK를 쓰지 않음). 런타임 의존성이 없고, Pleos 기기에 Play 서비스가 있는지 몰라도 되고, JVM으로 시험할 수 있다. `HttpURLConnection`은 PATCH를 못 보내서 갱신·도착·취소는 `documents:commit` + `updateMask`다.
- **데이터 모드**: Fake는 내장 시연 병원, 시연(release)은 서버 → 5초 안에 못 받으면 내장으로 대체, Real은 서버만. **release는 네트워크 없이도 끝까지 돈다** (문의 A2). 대체된 병원에는 카드를 서버로 보내지 않는다.
- **보안 규칙**은 "로그인했는가"가 아니라 "누구의 문서인가"로 막는다: 병원 코드가 맞는 브라우저만 직원 등록, 직원만 상태 변경·카드 읽기, 차는 자기 건만, 사진이 든 카드는 거부, 병원 코드는 아무도 못 읽음.
- **출발 뒤 갱신 규칙**: 남은 분이 바뀌고 60초가 지났을 때만 보낸다. 다만 처음 보낸 값이 목록의 어림값이면 내비가 준 첫 남은 시간은 기다리지 않고 바로 보낸다.
- **BuildConfig 함정**: `secrets.properties`만 바꾸면 Kotlin 증분 컴파일이 예전 값(상수 인라인)을 남겼다. Firebase 필드는 `String.valueOf("...")`로 상수가 아니게 했다.

- 새 의존성 (모두 버전 고정):
  - 웹 `firebase` 13.1.0 (Apache-2.0, 병원 웹 번들에만)
  - `firebase/`의 `firebase-tools` 15.34.1 (MIT, 개발 도구)

## 시연 방법

서버 없이 (release와 같음):

1. Pleos 에뮬레이터 Cold boot → 내비 화면을 한 번 띄운다 (안 그러면 위치를 몰라 대기 시간 순).
2. [진료 카드 만들기] → 증상 → [카드 만들기] → [가장 빨리 진료받을 곳 찾기] → 1위 → [출발].
3. GNB의 MeongCare 아이콘으로 돌아와 카드와 "시연용: 실제 병원에는 보내지 않았어요" → 기어 D → 도착 → P.

차 ↔ 병원 웹 (debug, PC):

1. `npm --prefix firebase run emulators` (켜 둔다) → `npm --prefix firebase run seed -- --reset`
2. `web/.env.example` → `web/.env.local` 복사 → `npm --prefix web run dev` → `http://localhost:5173/hospital/?h=demo-fast&code=fast-1234`
3. `secrets.properties`에 `FIREBASE_PROJECT_ID=demo-meongcare`, `FIREBASE_API_KEY=demo-key`, `FIREBASE_EMULATOR_HOST=10.0.2.2` (안 되면 `127.0.0.1` + `adb reverse tcp:8080 tcp:8080`, `adb reverse tcp:9099 tcp:9099`) → debug 빌드 설치 → debug 패널을 시연으로.
4. 병원 웹에서 대기 시간을 바꿔 알리고, 차에서 [새로 고침] → 순위가 바뀐다. [출발] → 병원 웹에 카드가 뜬다. 주행하면 남은 시간이 1분에 한 번 바뀐다.

**기획서 5번 "개발 계획"에 넣을 문장** (확인한 것만):

> 제휴 병원이 병원용 웹 화면에서 예상 대기 시간과 응급 접수 여부를 알리면, 차 앱은 Pleos NaviHelper로 받은 현재 위치에서의 이동 시간 어림값과 합쳐 "가장 빨리 진료받을 수 있는 순서"로 보여 준다 (Pleos 에뮬레이터에서 확인). 운전자가 정차 중 병원을 고르고 출발하면 NaviHelper로 그 병원까지 길안내가 시작되고, 진료 카드(반려견 정보·증상·병력·알레르기·복용 약)와 도착 예정 시간이 병원 화면에 전달된다 (사진과 차 위치는 보내지 않는다). 서버는 Firebase(Firestore, 익명 인증)이고, 서버에 닿지 못하면 시연용 병원 정보로 같은 흐름을 이어 간다. 새로운 Pleos 권한은 필요 없다.

(차 → 병원 웹 전달까지 Pleos 에뮬레이터 + PC Firebase 에뮬레이터에서 확인했다. 진짜 Firebase 프로젝트는 아직이다.)

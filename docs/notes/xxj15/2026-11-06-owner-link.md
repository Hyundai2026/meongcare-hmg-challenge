## 무엇을 했나

- **보호자 웹에 등록한 반려견 정보로 차의 진료 카드를 만든다.** 지금까지 차 앱은 샘플 "보리"로만 돌았다.
- 흐름 (TV 로그인 방식):
  1. 보호자가 폰 웹에서 반려견을 등록하고 [서버에 저장하고 차와 연결] → 동의한다. 브라우저에 있던 정보는 서버로 옮기고 브라우저에서 지운다.
  2. 차(정차 중) 처음 화면의 [보호자 웹과 연결] → 아주 큰 6자리 코드 (예: `K7P 3QX`).
  3. 보호자 웹 [차와 연결]에 코드를 입력하면 차에 "콩이 보호자와 연결했어요".
  4. 그 뒤 진료 카드와 병원에 보내는 카드에 그 반려견 정보가 들어간다. 웹에서 고치면 차가 다시 읽는다.
  5. 차 처음 화면 [연결 끊기]로 끊는다.
- 차에서는 글자를 입력하지 않고, 연결 화면은 정차 중에만 보인다.
- 기획서 담당자용 [docs/product/feature-facts.md](../../product/feature-facts.md)(기획서에 써도 되는 것 / 아직 아닌 것)를 만들고 이 기능까지 반영했다.
- 범위: 계획의 **필수 A(11/15 영상)**까지. 필수 B(앱을 다시 켜도 연결 유지, 웹의 연결된 차 관리·내 정보 지우기)는 계획 015로 넘긴다.

## 어떻게: 핵심 결정과 이유

- **사용자 결정 (2026-11-06, U1~U9 모두 추천안)**:
  - U1 보호자는 익명 계정. 로그인 화면 없이 빠르게 시연한다. 브라우저 데이터를 지우면 고칠 수 없다는 것을 동의 화면에 알린다.
  - U2 코드는 차가 만들고 폰에 입력한다. 6자(헷갈리는 0·1·I·L·O 뺀 31종), 10분, 한 번만. 차는 그 보호자의 프로필 문서 하나만 읽는다.
  - U3 사진은 보호자만 읽는 문서(`private/photo`)로 분리한다. 차는 사진을 읽지 못한다.
  - U4 11/15에는 코드만 (QR 없음).
  - U5 차 기기에 저장하지 않는다 (앱을 다시 켜면 다시 연결). PT 전에 연결 자격만 Keystore로 암호화해 저장한다. Room+SQLCipher 결정은 Keystore 파일로 바꾼다.
  - U6 동의 전엔 브라우저, 동의하면 한 번 옮기고 브라우저에서 지운다. 서버에 이미 있으면 덮어쓰지 않는다.
  - U8 보호자 페이지는 서버 설정이 있을 때만 Firebase를 동적 import한다.
  - U9 영상에서 보호자 웹은 PC 크롬 폰 크기로 연다.
- **연결된 뒤 읽지 못하면 보리로 대신하지 않는다.** 틀린 의료정보를 보이는 것보다 "불러오지 못했어요"가 안전하다.
- **연결 직후 서버 응답 전에 보리가 다시 보이지 않게** 했다 (tester가 찾은 버그). 공유 흐름의 마지막 값(보리)이 새 화면에 먼저 가던 것을 막았다:
  - 서버 응답을 기다리는 동안은 아무것도 내보내지 않는다.
  - 연결 상태와 값의 출처를 맞춰 본다 (연결됨이면 서버 값만).
  - 구독이 멈추면 마지막 값을 잊는다.
  - 이미 보리를 보던 화면에는 응답이 올 때까지 "시연용 샘플" 안내를 남긴다.
- **보안 규칙으로 막는 것** (R14~R24, 모두 PASS):
  - 동의 문서가 있어야 프로필을 쓴다.
  - 코드는 차 자기 uid·서버 시각으로만 만든다. 보호자는 만료 전·안 쓴 코드를 자기 uid·서버 시각으로 한 번만 claim한다.
  - 허가(`readers/{차}`)는 claim과 같은 한 번에 쓰기에서만 만든다 (`getAfter`).
  - 차는 허가가 있을 때 프로필 하나만 읽는다. 코드·프로필 목록 조회는 막는다.
- 확인한 Firebase 동작:
  - batch에서 `getAfter`가 claim을 본다.
  - 같은 코드 다시 만들기는 409다.
  - 10분 만료는 `createdAt + duration.value(10, 'm')`로 된다.
  - 허가는 있고 프로필이 없으면 404, 허가가 없으면 403이다. 그래서 차는 "등록 안 됨"과 "연결 끊김"을 구분한다.
- 같은 차를 허가가 남은 채 다시 연결하면 웹의 `set`이 update가 되어 거부됐다. 그래서 같은 조건의 update를 허용했다 (R19b).
- 차 쪽 서버 클라이언트(전송·익명 계정)는 병원과 반려견이 같이 쓴다. 같은 uid여야 규칙을 통과한다.
- 다시 읽기: 처음 화면이 보이는 동안(앱이 앞에 있을 때) 1분마다, [진료 카드 만들기]·[새로 만들기] 때. 주행 화면·백그라운드에서는 읽지 않는다. 연결 코드 화면도 보이는 동안만 2초마다 묻는다.
- 기존 테스트를 지키려고 `PetProfileLoad`·`FakePetProfileSource`·`SourcePlan`은 고치지 않았다. 새 구성은 `di/PetPlan.kt`에 둔다.

## 시연 방법 (11/15 영상)

준비 (PC):

1. `npm --prefix firebase run emulators` (켜 둔다) → `npm --prefix firebase run seed -- --reset`
2. `npm --prefix firebase run preflight -- --fix` → 모두 PASS
3. `web/.env.local`에 에뮬레이터 값(`.env.example` 처음 세 줄) → `npm --prefix web run dev` → 크롬 기기 모드(폰 크기)로 `http://127.0.0.1:5173/`
4. 차: debug 빌드, debug 패널 "시연", `secrets.properties`에 에뮬레이터 값 (Pleos는 Cold boot 뒤 내비 화면을 한 번 띄운다)
5. 병원 웹 `http://127.0.0.1:5173/hospital/?h=demo-fast&code=fast-1234`

영상 순서 제안:

1. 폰 웹에서 콩이 등록 → [서버에 저장하고 차와 연결] → 동의
2. 차(정차) [보호자 웹과 연결] → 큰 코드
3. 폰 [차와 연결] → 코드 입력 → 차 "콩이 보호자와 연결했어요" → [확인]
4. [진료 카드 만들기] → 증상 → 카드에 콩이의 의료정보
5. [가장 빨리 진료받을 곳 찾기] → 1위 → [출발]
6. 병원 웹에 콩이 카드 → 주행 화면 → 병원 [카드 확인] → 차에 확인 한 줄

**기획서 5번 "개발 계획"에 넣을 문장** (확인한 것만):

> 보호자는 폰 웹에서 반려견 프로필과 의료정보를 등록하고 서버 저장에 동의한다. 차에서는 정차 중 [보호자 웹과 연결]을 누르면 6자리 연결 코드가 크게 뜨고, 보호자가 폰에 그 코드를 입력하면 차가 그 반려견 정보로 진료 카드를 만든다. 차에서는 글자를 입력하지 않으며, 연결 화면은 주행 중에는 보이지 않는다. 연결된 차는 그 반려견의 진료용 정보만 읽을 수 있고 사진은 읽을 수 없으며, 차에서 연결을 끊을 수 있다. 연결 코드는 10분 동안 한 번만 쓸 수 있다.

(Pleos 에뮬레이터, PC의 Firebase 에뮬레이터, 폰 크기 브라우저에서 확인했다. 실제 운영 서버와 실제 폰은 아직이다.)

## 주의점 / 남은 일

- **제출 APK에는 이 기능이 없다.** 012 U5대로 release에 서버 설정을 넣지 않아 연결 버튼이 없고 보리로 돈다. 연결 장면은 영상과 PT로 보인다. 기획서에도 그렇게 쓴다 (feature-facts.md).
- 앱을 다시 켜면 차의 익명 uid가 바뀌어 이전 허가 문서가 서버에 남는다 (차는 읽지 못한다). 웹 "연결된 차"에서 지울 수 있게 한다 (015).
- 다른 보호자와 새로 연결할 때 이전 허가를 지우지 못하면 넘어간다 (서버에 남지만 차는 읽지 않는다).
- 웹 문구 "'콩이'가 보이는지": 받침 있는 이름(예: 보름)이면 조사가 어색하다.
- 동의 뒤 브라우저 지우기에 실패해도 "옮겼어요"라고 한다 (다음에 열면 서버 것을 보여 주고 브라우저 정보는 남는다).
- 계획 015 (PT 전): 필수 B(단계 10·11), 있으면 좋음 A~F 중 고를 것 (QR, 마지막 프로필 암호화 캐시, 실제 폰 LAN 시연, 계정 업그레이드, 차 카드 사진, 진짜 Firebase + Hosting).
- 012에서 넘어온 것: U5(11/15 APK에 Firebase 설정), K9(PT 빌드).

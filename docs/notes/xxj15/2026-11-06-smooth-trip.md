## 무엇을 했나

- **시연 병원 ↔ 차 앱 연결을 매끄럽게 했다.** 차가 [출발]하면 병원 웹에 카드가 "새 환자"로 강조되어 뜨고, 남은 시간이 몇 초마다 바뀐다. 병원 직원이 **[카드 확인]**을 누르면 운전 중인 차 화면에 "병원이 카드를 확인했어요"가 뜬다 (양방향).
- **길안내 화면을 완성했다.** 정차 중 카드 위에 안내 영역(목적지·큰 남은 분·도착 예정 시각·출발 때 알린 대기·진행 막대·전송/확인 상태), 주행 화면은 아주 큰 남은 분 + 목적지 + 진행 막대 + 확인 한 줄, 도착하면 "○○에 도착했어요 · 이 카드를 접수처에 보여 주세요".
- **시연 도착 순간 내비가 MeongCare를 덮던 문제를 없앴다.** 시연 전 점검 스크립트(`preflight`)와 병원 웹의 서버 주소·연결 표시로, 차와 병원 웹이 서로 다른 서버에 붙는 사고를 막는다.

## 어떻게: 핵심 결정과 이유

- **처음 본 문제 (에뮬레이터 직접 확인)**
  1. Firebase 에뮬레이터가 IPv4(사용자 터미널)와 IPv6(이전 Claude 세션이 띄우고 안 끈 것) 두 벌 떠 있었다. 차(`adb reverse` → 127.0.0.1)와 병원 웹(`localhost` → ::1)이 서로 다른 서버를 봐서 카드가 병원 웹에 안 떴다. IPv6 쪽은 정리했다.
  2. 병원 갱신이 60초 간격이라 시연(1분을 2초로 줄임)에서 "37분 → 8분 → 도착"으로 튀었다.
  3. 앱이 내비 경로를 취소하면(`cancelRoute`) 내비 앱이 앞으로 나와 MeongCare를 가렸다. 시연 도착 때 "도착했어요" 대신 내비 빈 지도가 보였다.
  4. 주행 화면은 넓은 화면 가운데 작은 두 줄, 정차 중 안내는 카드 머리 제목만 바뀌었다.
- **사용자 결정 (2026-11-06)**: U1 병원 [카드 확인] → 차 표시 넣기 (서버에서 온 병원만, 내장 시연 병원은 흉내 내지 않음). U2 시연 모드에서 시연 도착·[닫기] 때 내비 경로를 남긴다. U3 [안내 취소] 뒤 앱을 다시 앞으로 가져오기를 시험한다. U4 주행 화면 = 큰 남은 분 + 병원 + 진행 막대 + 확인 한 줄.
- **U3 결과: 안 된다.** `startActivity`는 Android 14 백그라운드 실행 제한(`BAL_BLOCK`), `moveTaskToFront`는 새 권한(`REORDER_TASKS`)이 필요하다. 그래서 앱 [안내 취소] 뒤에는 지금처럼 내비가 보인다 (알려진 한계, sdk-notes에 기록).
- **U2 방법**: `NaviClient`에 "닫을 때 경로를 남길지"(`RouteOnClose.CANCEL/KEEP`)를 받는 오버로드를 더했다. 시연 도착·[닫기]만 KEEP → 리스너 해제·`release()`만 해서 내비가 앞에 나오지 않는다. 남은 경로는 다음 `requestRoute`가 바꾸고, 이전 경로의 취소 알림은 어댑터가 원래 거른다 (에뮬레이터에서 다시 확인).
- **갱신 간격** (`di/TripTiming.kt`): 시연 길안내는 도착 예정 4초·확인 읽기 4초, 실제 길안내는 60초·15초. 확인 읽기는 안내 한 번에 묶여 있고 확인·도착·취소·건 삭제·[닫기]에 멈춘다 (상주 폴링이 아님).
- **카드 확인 읽기**: 차는 자기 건을 `GET …/cases/{id}?mask.fieldPaths=acknowledgedAt`로 읽는다. 병원이 [완료]로 지운 건은 403이 와서 "건 없음"으로 멈춘다 (에뮬레이터 확인).
- **보안 규칙 강화**: `acknowledgedAt`은 직원만, **서버 시각으로, 확인 전인 건에 한 번만**. 점검 R9~R13 추가 (R1~R13 모두 PASS).
- **진행 막대의 시작값**은 `GuidanceUiState`가 아니라 `TripState.startMinutes`(이번 안내에서 본 가장 큰 남은 분)에 둔다. 기존 테스트 약 30곳이 `Guiding(이름, 분)`을 동등성으로 비교하고, ViewModel은 내비가 앞에 있는 동안 구독을 끊어 돌아오면 시작값이 다시 잡히기 때문이다.
- **안내 영역 색**은 테마와 상관없는 고정색(파랑, 도착은 초록, 흰 글자 대비 5:1 이상). [병원에 전화] [안내 취소]는 화면 아래 고정 줄에 그대로 둔다 (카드를 스크롤해도 보이게).
- **주행 화면**에는 도착 예정 시각·대기 정보·전송 상태·시연용 표시를 넣지 않는다 (정차 화면에만). 진행 막대는 Material 진행 표시(값 변화 애니메이션)가 아니라 상자 두 개로 그린다.
- **익명 토큰 미리 갱신**: 만료 5분 전부터 같은 uid로 갱신 (securetoken REST, form 몸통). 거부(400)면 새로 가입. PT 때 앱을 1시간 넘게 켜 두면 서버 연결이 끊기던 문제를 막는다.
- **병원 웹**: 새 환자 주황 강조·탭 제목 "(N) 새 환자 · …", [카드 확인] 버튼, 위에 "서버: 에뮬레이터 127.0.0.1:8080 · … · 실시간 연결됨". 호스트가 `localhost`·`::1`이면 빨간 경고.
- **시연 전 점검** `npm --prefix firebase run preflight` (PF1~PF6): 127.0.0.1 응답, 시드, [::1]의 다른 에뮬레이터, adb reverse, 30분 안 대기 정보. 비밀 파일(웹 env·차 설정)은 읽지 않는다. PF6은 확인 중에 실제로 겪어서 더했다: 시드하고 30분이 지나면 모든 병원이 "대기 정보 지남"이 되어 차 목록에 1위가 없다.
- `firebase.json`에 Auth·Firestore host `127.0.0.1`을 고정했다 (다음에 에뮬레이터를 켤 때 적용).

- 새 의존성 없음.

## 시연 방법

차 ↔ 병원 웹 (debug, PC):

1. `npm --prefix firebase run emulators` (켜 둔다) → `npm --prefix firebase run seed -- --reset`
2. `adb reverse tcp:8080 tcp:8080`, `adb reverse tcp:9099 tcp:9099`
3. 병원 웹 개발 서버 → `http://localhost:5173/hospital/?h=demo-fast&code=fast-1234`. 화면 위 "서버:" 줄이 `127.0.0.1:8080 … 실시간 연결됨`인지 본다 (빨간 경고가 있으면 웹 env 파일의 호스트를 `127.0.0.1`로).
4. **시연 직전 `npm --prefix firebase run preflight`** → 모두 PASS. PF6이 실패하면 병원 웹에서 [병원 상태 알리기].
5. 차: 카드 → [가장 빨리 진료받을 곳 찾기] → 1위 → [출발] → GNB의 MeongCare 아이콘 → 안내 영역 → 기어 D (주행 화면) → 병원 웹 [카드 확인] → 차에 "병원이 카드를 확인했어요" → 도착 → P → 도착 카드.

**기획서 5번 "개발 계획"에 넣을 문장** (확인한 것만):

> 운전자가 정차 중 병원을 고르고 출발하면 진료 카드가 병원 화면에 "새 환자"로 표시되고, 도착 예정 시간이 주행에 따라 갱신된다. 병원 직원이 병원 화면에서 [카드 확인]을 누르면 운전 중인 보호자의 차 화면에 "병원이 카드를 확인했어요"가 표시되어, 보호자는 병원이 준비하고 있다는 것을 운전 중에도 알 수 있다. 주행 중 화면은 큰 남은 시간과 진행 막대, 확인 한 줄만 보이고 버튼·입력·애니메이션이 없다 (AAOS 주행 규제에 맞춤). 정차하면 목적지·도착 예정 시각·병원 대기 정보·전송 상태를 보여 주고, 도착하면 "이 카드를 접수처에 보여 주세요"와 함께 진료 카드를 보인다. 새로운 Pleos 권한은 필요 없다.

(Pleos 에뮬레이터 + PC Firebase 에뮬레이터에서 확인했다. 실차·진짜 Firebase 프로젝트는 아직이다.)

## 주의점 / 남은 일

- **사용자 할 일**: 병원 웹을 `--mode emulator`로 띄울 때 쓰는 env 파일(`web/.env.emulator.local`)의 에뮬레이터 호스트가 `localhost`다 (화면 경고로 확인). `127.0.0.1`로 바꾼다. 에이전트는 그 파일을 읽지 않는다.
- 다음에 Firebase 에뮬레이터를 다시 켜면 `firebase.json`의 host 고정이 적용된다.

- 시연 모드는 도착 뒤 내비에 경로가 남는다 (다음 출발 때 바뀐다). PT 중 내비 화면을 보여 줄 때 참고.

## 무엇을 했나

README를 심사위원·방문자용으로 다시 구성했다. 사용자 요청: 팀원 개발 가이드(브랜치, 개발 순서, 명령어, 규칙)는 빼고, Team-FINCH/finch-frontend README처럼 주요 기능과 기술 요소가 잘 보이게.

- 순서: 머리(배너, 한 줄 소개, 큰 배지, 바로가기, 시연 GIF) → ✨ 주요 기능 → 📱 화면 → 🚗 차량이라서 가능한 것(+ 서비스 생태계 Mermaid) → 🛠 기술 스택 → 💡 기술적 포인트 → 🎬 시연 범위 → 🚀 실행 가이드 → 🧑‍💻 팀
- 주요 기능: 핵심 4개는 번호 붙은 소제목 + 장면 사진, 그 아래 "흐름 / 기능 / 설명" 표로 전체 기능 9줄.
- 화면: 접혀 있던 9장을 3열 그리드로 펼쳤다.
- 기술 스택: shields.io 배지 + `<details open>` 분류표(옛 "SDK와 버전" 표를 합침) + 앱 계층 Mermaid 다이어그램 + 폴더 구조.
- 기술적 포인트(새로 씀): 주행 상태 UX, SDK 래퍼 + Fake 데이터 모드, 콜백 → 코루틴, 병원 순위, 연결 코드, 서버 없이 동작, 품질 관리. 모두 docs/architecture.md에 있는 사실만 썼다.
- 시연 범위 표와 로컬 서버 시연은 `<details>`로 접었다. 내용은 그대로다.
- 팀원 개발 가이드는 지우지 않고 `docs/conventions/team-guide.md`로 옮겼다. bmad-guide.md의 링크도 고쳤다.

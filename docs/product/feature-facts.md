# 기획서에 써도 되는 것 / 아직 아닌 것

기획서 담당자용이다. 앱에서 **실제로 확인된 기능만** 기획서에 "된다"고 쓰기 위한 표다.

- 기준: 2026-11-12 dev (`309e9b6`). 계획 014(보호자 연결), 015(근처 동물병원), 016(고정 시연 위치), 010(음성 증상 입력)과 대회 공지 "공모전 개발 범위 및 기술 문의 안내"(2026-11-12 확인)까지 반영했다. 기능이 바뀌면 이 표부터 고친다.
  - 같은 날 계획 017(소리 안내)을 중간 반영했다. 확인 전이라 3·4번 표에만 적었다.
- 왜 필요한가: 공모전 출품 유의사항에 "제출 서류의 내용이 사실과 다르면 선정이 취소될 수 있다"가 있다 ([../contest/requirements.md](../contest/requirements.md)).
- "확인한 곳"의 에뮬레이터는 PC에서 돌린 Pleos 차량 에뮬레이터다. **실차에서는 아무것도 확인하지 않았다.**
- 근거는 각 개발 노트([../notes/](../notes/), 팀원별 폴더)의 "확인" 항목이다.

## 2. 조건을 붙여서 쓸 것

| 기능 | 기획서에 쓸 때 |
|---|---|
| 병원 목록 | 제휴 병원은 지금 **시연용 가상 병원 5곳**이다. "제휴 병원이 대기 시간을 알리는 구조"로 쓰고, 실제 제휴 병원이 있다고 쓰지 않는다 |
| 동물병원 문의·응답 (020) | 카드 [동물병원 찾기]는 가까운 3곳에 수용 여부를 묻고 답변을 비교해 출발한다. **병원 이름(별숲동물의료센터 등 5곳)은 가상이고, 병원 답변은 앱 안의 시연 응답이다. 병원 웹과 연결하지 않는다** (화면 문구 "동물병원 웹에서 답변하면 바로 반영"은 계획된 구조다. 사용자 결정 2026-11-13: 화면에는 시연 표시를 하지 않으므로 기획서·영상 자막에 반드시 적는다). 출발 시 진료 카드는 앱 안 시연 전송이라 병원 웹으로 가지 않는다. 지도는 그린 그림이다 |
| 근처 동물병원 (2026-11-13부터 끔) | 병원 이름·위치·전화는 카카오의 실제 정보지만 **대기 시간은 시연용 예시**다 (화면에 "(예시)"). 근처 병원에는 진료 카드를 보내지 않는다. **PC의 Firebase 에뮬레이터 서버에서만 확인했고, 제출 APK에는 없다** (제출 APK는 제휴 시연 병원만 보인다). Pleos 에뮬레이터의 내비 위치로 검색하는 것은 확인하지 못했다 |
| 이동 시간 | 병원을 비교할 때의 이동 시간은 **직선 거리로 어림한 값**이다. 출발한 뒤의 남은 시간은 내비 값이다 |
| 현재 위치 | 차량 기기에서는 내비 위치, 일반 폰·태블릿에서는 **시연용 고정 위치(서초동)**다. 폰 GPS는 쓰지 않는다 |
| 음성 증상 입력 | **정차 중에만** 된다. 말에서 증상을 찾는 것은 **AI가 아니라 키워드 규칙**이다 ("구토는 안 했어요" 같은 부정은 알아듣는다). 실제 마이크는 Pleos 에뮬레이터에서만 확인했고 실차는 아직이다. 제출 APK를 일반 폰에서 돌리면 예시 문장이 "시연용"으로 나온다 |
| 서버 | Firebase로 만들었지만 **PC의 Firebase 에뮬레이터에서만** 확인했다 (근처 병원 검색 함수 포함). 실제 운영 서버는 아직이다 |
| 병원에 전화 | 전화 앱을 여는 것까지다 (걸지 않는다). Pleos 에뮬레이터에서는 전화 앱이 열렸지만 번호가 보이지 않았다. 실차에서 되는지는 모른다 (주최측은 개별 기술 문의에 답하지 않는다고 공지했다) |
| 주행 중 사용 | 주행 중에도 앱 화면이 보이도록 선언했고 에뮬레이터에서 동작한다. 실차·앱 심사에서 허용되는지는 모른다 (위와 같은 이유로 답을 기대하지 않는다). 공모전 심사는 App Market 입점 심사가 아니다 (11-12 공지) |
| 도착 감지 | 실제 주행에서는 내비의 도착 신호를 쓰도록 만들었지만, 에뮬레이터에서는 차가 움직이지 않아 시연용 도착으로 보였다 |
| 반려견 정보 | 보호자 웹과 연결하기 전에는 **샘플 반려견 "보리"**로 카드를 만든다 (화면에 시연용이라고 표시) |
| 보호자 웹 연결 | **PC의 Firebase 에뮬레이터(로컬 서버)에서만** 확인했다. **제출 APK에는 서버 설정이 없어 연결 버튼이 없고 "보리"로 돈다.** 연결 장면은 시연 영상과 PT에서 보인다. 보호자 계정은 익명 계정이라 브라우저 데이터를 지우면 그 정보를 고칠 수 없다. 앱을 다시 켜면 다시 연결해야 한다 (PT 전 개선 예정) |

## 3. 쓰면 안 되는 것 (아직 없음)

| 쓰고 싶어질 문장 | 사실 |
|---|---|
| "보호자 웹에 등록한 정보가 차에 자동으로 뜬다" | 코드로 **한 번 연결해야** 뜬다 (자동이 아니다). "차 화면의 코드를 폰에 입력해 연결하면"으로 쓴다. 위 2번의 조건(로컬 서버, 제출 APK에는 없음)을 같이 쓴다 |
| "운전 중에 음성으로 증상을 말한다" | 음성 입력은 **정차 중** 증상 고르기 화면에서만 된다. 주행 중에는 아무 입력도 받지 않는다 |
| "음성으로 안내한다", "병원 확인을 소리로 알려 준다" | 코드는 dev에 있다 (계획 017: 출발·카드 전송·병원 확인·도착을 소리로, 2026-11-12 중간 반영). **그러나 앱의 출발~도착 흐름에서 소리가 나는지는 아직 확인하지 못했다.** Pleos TTS가 한국어로 재생되는 것만 시험 화면으로 확인했다. 확인 전에는 "PT 전 완성 예정"으로 쓴다 |
| "AI가 증상을 정리해 진료 카드를 만든다", "AI가 말을 이해해 증상을 고른다" | AI(LLM)를 쓰지 않는다. 받아쓰기는 Pleos 음성 인식 엔진, 증상 찾기는 키워드 규칙, 카드는 등록 정보와 고른 증상을 규칙대로 합친다 |
| "차 마이크 소리를 AI 서버로 보내 분석한다" | 공지로 금지됐다: "차량 마이크 음성을 외부 음성 인식 서비스로 보내는 방식은 … 사용할 수 없습니다". 밖으로 보낼 수 있는 것은 받아쓴 글자뿐이고, 지금은 글자도 보내지 않는다 |
| "주변 동물병원을 모두 검색한다", "근처 병원의 실제 대기 시간을 보여 준다" | 5km 안 최대 15곳이고, 대기 시간은 예시다. 제출 APK에는 근처 병원이 없다 (위 2번) |
| "Gleo 음성 명령으로 앱을 부른다" | 공모전 참가팀은 Gleo를 별도 검토·승인 없이 **쓸 수 있다** (11-13 운영사무국 정정. 11-12 공지의 "신청할 수 없다"는 바뀌었다). 그러나 **우리 앱에는 구현하지 않았다**. 구현하고 에뮬레이터에서 확인하기 전에는 "향후 계획"으로 쓴다 |
| "Pleos LLM으로 …" | 공모전 기간에 제공되지 않는다 (11-12 공지) |
| "차량 실내 온도·문·창문 등 차량 데이터를 활용한다", "공조를 조절한다" | Pleos Vehicle SDK는 연결만 해 두고 **아무 값도 읽지 않는다**. 차량 제어(Vehicle Control)는 콘솔 "준비 중"이고 새 권한이 필요해 쓰지 않는다 |
| "QR·링크로 진료 카드를 공유한다", "진료 이력·다음 진료 일정" | 없다 |
| "실차에서 검증했다" | 에뮬레이터에서만 확인했다 |

## 4. 기술 활용성 칸에 쓸 Pleos SDK

| SDK | 쓰는 곳 | 상태 |
|---|---|---|
| NaviHelper | 병원까지 경로 안내 시작, 현재 위치(병원 순위·근처 병원 검색의 기준), 도착 예정 시간, 도착 신호 | 사용 중 (도착 신호는 에뮬레이터에서 확인 불가) |
| SpeechToText | 정차 중 음성으로 증상 고르기 (`ON_DEVICE`: 차 안의 음성 엔진이라 네트워크와 앱 등록이 필요 없다) | 사용 중 (010). 콘솔은 "준비 중"이지만 대회 공지(11-12)가 공모전 사용을 허용했다 |
| TextToSpeech | 병원 가는 길의 사건을 소리로 알림 (계획 017, `ON_DEVICE`) | 공모전 사용 허용 (11-12 공지). 코드와 권한(`TTS_SERVICE`, 팀 승인)은 dev에 있다. 앱 흐름 확인 전이라 "PT 전 완성 예정"으로 쓴다 |
| FusedLocation | 없음 | 공모전 사용 허용 (11-12 공지). 만들지 않았다 (차량 기기에서는 NaviHelper로 위치를 얻는다) |
| Vehicle | 연결만 | 기능 없음 |

- 주행·정차 판단은 Pleos SDK가 아니라 **안드로이드 자동차 표준 API**(주행 규제 신호)다. Pleos SDK로 쓰지 않는다.
- 선언한 Pleos 권한은 `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`, `STT_SERVICE`, `TTS_SERVICE` 네 개다 (모두 2026-11-03 팀 승인).
- Pleos 밖에서 쓰는 것: Firebase(Firestore, 익명 로그인, 근처 병원 검색 함수), 카카오 로컬 API(함수만 키를 안다). 외부 API 사용은 주최측이 허용했다 (문의 A1). Claude API는 쓰지 않는다.

## 5. 그대로 옮겨도 되는 문장 (기획서 5번 "개발 계획")

> 운전자가 정차 중 병원을 고르고 출발하면 진료 카드가 병원 화면에 "새 환자"로 표시되고, 도착 예정 시간이 주행에 따라 갱신된다. 병원 직원이 병원 화면에서 [카드 확인]을 누르면 운전 중인 보호자의 차 화면에 "병원이 카드를 확인했어요"가 표시되어, 보호자는 병원이 준비하고 있다는 것을 운전 중에도 알 수 있다. 주행 중 화면은 큰 남은 시간과 진행 막대, 확인 한 줄만 보이고 버튼·입력·애니메이션이 없다 (AAOS 주행 규제에 맞춤). 정차하면 목적지·도착 예정 시각·병원 대기 정보·전송 상태를 보여 주고, 도착하면 "이 카드를 접수처에 보여 주세요"와 함께 진료 카드를 보인다. 새로운 Pleos 권한은 필요 없다.

(출처: [../notes/xxj15/2026-11-06-smooth-trip.md](../notes/xxj15/2026-11-06-smooth-trip.md). Pleos 에뮬레이터와 PC의 Firebase 에뮬레이터에서 확인했다.)

> 보호자는 폰 웹에서 반려견 프로필과 의료정보를 등록하고 서버 저장에 동의한다. 차에서는 정차 중 [보호자 웹과 연결]을 누르면 6자리 연결 코드가 크게 뜨고, 보호자가 폰에 그 코드를 입력하면 차가 그 반려견 정보로 진료 카드를 만든다. 차에서는 글자를 입력하지 않으며, 연결 화면은 주행 중에는 보이지 않는다. 연결된 차는 그 반려견의 진료용 정보만 읽을 수 있고 사진은 읽을 수 없으며, 차에서 연결을 끊을 수 있다. 연결 코드는 10분 동안 한 번만 쓸 수 있다.

(출처: [../notes/xxj15/2026-11-06-owner-link.md](../notes/xxj15/2026-11-06-owner-link.md). Pleos 에뮬레이터, PC의 Firebase 에뮬레이터, 폰 크기 브라우저에서 확인했다. 실제 운영 서버와 실제 폰은 아직이다.)

> 정차 중 증상 고르기 화면에서 마이크 버튼을 누르고 한 문장으로 말하면, Pleos SpeechToText SDK(`ON_DEVICE`: 차량 안의 음성 엔진이라 네트워크와 앱 등록이 필요 없다)가 받아쓴 문장을 키워드 규칙으로 증상 버튼에 옮긴다. 사용자는 버튼으로 확인·수정한다. 버튼만으로도 같은 카드를 만들 수 있다. 음성은 차 밖으로 보내지 않는다.

(출처: [../notes/xxj15/2026-11-05-voice-input.md](../notes/xxj15/2026-11-05-voice-input.md). Pleos 에뮬레이터에서 실제 마이크로 확인했다. 실차는 아직이다.)

> 병원 찾기 화면은 제휴 병원(병원이 대기 시간을 직접 알린다)과 현재 위치 5km 안의 동물병원(카카오 로컬 API로 검색)을 한 목록에 "이동 시간 + 대기 시간"이 짧은 순으로 보여 준다. 카카오 키는 앱에 넣지 않고 서버 함수만 알며, 차 위치는 약 100m 단위로 줄여 보내고 저장하지 않는다. 제휴하지 않은 병원은 대기 정보가 없어 시연에서는 예시 값을 붙였고, 진료 카드는 제휴 병원에만 보낸다.

(출처: [../notes/CYJhub/2026-11-08-nearby-vet-search.md](../notes/CYJhub/2026-11-08-nearby-vet-search.md). 일반 태블릿 에뮬레이터와 PC의 Firebase 에뮬레이터에서 확인했다. 제출 APK에는 없다.)
